# Circle Windows Native 0.4.2

## Исправление CI: проверка установщика (10 ноября 2026)

В предыдущем workflow тест Inno Setup запускал графический EXE через `&` и затем проверял `$LASTEXITCODE`. В Windows PowerShell при запуске GUI-программы код может остаться `$null`, что давало ложное `Installer failed:` без числа. Теперь `tool/verify_installer.ps1` дожидается завершения через `Start-Process -Wait -PassThru`, проверяет `Process.ExitCode`, наличие всех файлов из сборки Flutter, размеры и SHA-256 критичных бинарных файлов. В случае ошибки в GitHub Actions сохраняются артефакты `Circle-Windows-CI-Diagnostics` с логом Inno Setup и отчётом. Проверка сохраняется обязательной, не отключена. На Windows при локальной сборке `build-installer.ps1` использует ту же проверку.

**Важно:** это исправление CI-процедуры, версия приложения остаётся 0.4.2. Успешная проверка установки в GitHub ещё не доказывает, что окно программы запускается на пользовательском ПК: тест запуска проводится отдельно на Windows.


**Твой круг. Твои люди.** Нативный Windows-клиент Circle, совместимый с PHP-сервером **Circle 5.2.3**. Приложение **не использует WebView**: экраны, навигация, редакторы, аудио/видео и звонки реализованы во Flutter. Подключение к тому же серверу через HTTPS Mobile API (`/api/mobile.php`); отдельная база не нужна.

## Исправления запуска 0.4.2

После сообщений о том, что установленный EXE не открывается, переработана последовательность запуска: Flutter показывает первый экран сразу, а управление окном и декодер медиа запускаются позднее. Ошибки восстановления сохранённого токена не оставляют бесконечный индикатор загрузки. Ошибки Flutter/Dart пишутся в `%LOCALAPPDATA%\Circle\logs\startup.log` (без секретов и текстов переписки). Рядом с EXE упаковываются требуемые библиотеки Visual C++ Runtime из Visual Studio Windows runner; инсталлятор проходит дополнительную проверку файлов на GitHub.

**Если 0.4.2 не открывается:** открой в меню «Пуск» пункт «Circle - диагностика запуска» или файл `tools\Circle-Diagnostics.cmd` в папке установки. Скрипт создаст `%LOCALAPPDATA%\Circle\diagnostics\last-launch-report.txt`, проверит библиотеки и процесс, покажет код выхода. Перед отправкой лога проверь наличие личных путей. Сам EXE отдельно от папки `data` и DLL запускать нельзя. Эта версия не проходила тест на вашем компьютере; выяснение причины подтвердит диагностический отчёт.

**Дополнительное исправление GitHub Static analysis.** Удалён неиспользуемый импорт `dart:typed_data` из `lib/main.dart`; он вызывал `unused_import` и блокировал workflow. Версия остаётся 0.4.2, поскольку предыдущий релиз не прошёл сборку.

**Исправление 0.4.2.** Устранены ошибки `duplicate_definition` в `design.dart` и `ambiguous_import` / `invocation_of_non_function` из-за названия `CircleAvatar`. Клиент использует `CircleUserAvatar`; обновлена инициализация LiveKit. Исходники не компилировались локально, проверка результата — в GitHub Actions.

## Как получить установщик в GitHub

1. Распаковать **весь** ZIP в корень репозитория GitHub (не добавлять ZIP одним файлом). Убедиться, что присутствует `.github/workflows/windows.yml`.
2. Сохранить изменения в `main`. Открыть **Actions → Circle Windows build**. Сборка запускается автоматически или вручную через **Run workflow**.
3. После успешной сборки скачать `Circle-Windows-Setup` в разделе **Artifacts**. Внутри будет `Circle_Windows_0.4.2_Setup.exe`. Отдельно публикуется портативный `Circle-Windows-Portable`.
4. Установить приложение на Windows 10/11 x64. Вход по HTTPS-адресу Circle, по умолчанию `https://acircle.ru`.

Сборка на GitHub использует Flutter stable, Visual Studio на Windows runner, Inno Setup 6; проверяет `flutter analyze --no-fatal-infos`, `flutter test` и компиляцию в release. При ошибке компиляции **артефакт не публикуется**. Для локальной сборки на Windows: `powershell -ExecutionPolicy Bypass -File .\build-installer.ps1`.

## Достоверность реализации

**Это тестовый исходный проект, а не сертификат полного паритета с сайтом.** Реализация кода не означает, что функциональность уже прошла реальные тесты. В этой среде нет Flutter SDK/Windows toolchain, поэтому **здесь не запускались `flutter analyze`, `flutter test`, сборка EXE и физические звонки**. Проверены структура проекта, Python-скрипт подписи релиза, синтаксическая сбалансированность исходников, наличие маршрутов в PHP 5.2.3 и целостность архива. GitHub выполнит фактическую компиляцию.

**Остаются ограничения API сервера 5.2.3:** полный редактор сообществ и прав, группы/роли, часть системы друзей (запросы/поиск), админские инструменты модерации, расширенный профиль, редактирование публикаций, репосты и отправка некоторых видов вложений не имеют полного набора Mobile API и не могут быть перенесены только клиентом. Фоновый push Windows отсутствует: сервер регистрирует push-токены только для `android`/`ios` и возвращает `delivery_enabled:false`. Демонстрация экрана и групповые личные звонки ещё требуют отдельного тестирования и UI. Подробности в `docs/API-COMPATIBILITY.md`.

## Автообновления через GitHub Releases

Без настроенного подписанного канала проверка обновлений показывает пояснение и не устанавливает ничего автоматически. Это сделано намеренно ради безопасности.

1. Один раз установить Python `cryptography` на доверенной машине: `python -m pip install cryptography`.
2. Сгенерировать **приватный** ключ: `python tool/sign_release.py --generate-key --private-key release-private-key.pem`. Скрипт выведет `PUBLIC_KEY_BASE64`. Приватный PEM **не публиковать**.
3. Сохранить в GitHub **Settings → Secrets and variables → Actions**:
   - Secret `CIRCLE_UPDATE_PRIVATE_KEY_PEM` — полное содержимое PEM.
   - Variable `CIRCLE_UPDATE_PUBLIC_KEY` — выведенный Base64.
   - Variable `CIRCLE_UPDATE_URL` — `https://github.com/OWNER/REPO/releases/latest/download/update-manifest.json` (подставить имя репозитория).
4. Сохранить эти переменные **до сборки** устанавливаемого клиента: публичный ключ и URL встраиваются через `--dart-define`.
5. Сделать тег **`v0.4.2`** и запустить workflow. При успешном тестировании GitHub сформирует установщик и опубликует в Releases подписанный `update-manifest.json`. Приватный PEM в артефакты не попадает.
6. Для следующих релизов обновлять версии **согласованно** в `pubspec.yaml`, `lib/main.dart`, `installer/Circle.iss`, `build-installer.ps1`, workflow. В шаге релиза текущий тег должен совпадать с версией.

При установке поверх предыдущей версии Inno Setup использует постоянный `AppId`; пользовательские данные на сервере и локальный токен Windows не удаляются. Переход с 0.3.2 на 0.4.2 проверяется отдельно.

## Безопасность

- Токен хранится через Windows secure storage; не добавляется к URL файлов, передаётся только в `Authorization`.
- Исходный PHP-сайт и его база **не изменены**. Никогда не загружайте Flutter ZIP через админку обновлений сайта.
- URL сервера валидируется как HTTPS. Обновление подписано Ed25519, установщик сравнивается по SHA-256, HTTPS-редиректы проверяются.
- Пользовательская сессия не перенастраивается без входа и не зависит от обновления UI.
