## Исправление CI: отсутствует `tool/test_installer_ci.py`

Если сборка завершилась на `Validate project files` сообщением `can't open file .../tool/test_installer_ci.py`, это означает, что файл не попал в GitHub checkout (хотя он присутствовал в полном исходном ZIP). В данном исправлении проверка установщика перенесена внутрь `tool/validate_package.py`, который уже выполняется GitHub. Дополнительный отдельный тест запускать не требуется. **Замените весь файл `.github/workflows/windows.yml` и `tool/validate_package.py`**, либо загрузите содержимое этого полного ZIP в корень репозитория. Новая проверка сообщает о недостающих скриптах по имени.

Запуск версии после сборки и сам механизм обновления от этого исправления не меняются. Если GitHub использует старую версию workflow, убедитесь, что запускается новая сборка из ветки, куда сохранены файлы.

# Circle Windows Native 0.6.1 — самостоятельное приложение для Windows

**Приложение не использует WebView.** Интерфейс написан на Flutter, данные и пользовательские аккаунты поступают с Circle 5.2.3 по HTTPS Mobile API. Сайт остаётся на PHP/MySQL на обычном хостинге. База данных и пользовательский контент в установщик не входят.

## Что изменено относительно 0.4.2

- Создана система **подписанных GitHub Releases с автоматической проверкой при запуске**, запросом подтверждения, загрузкой полного ZIP-runtime, проверкой Ed25519/SHA-256, локальной заменой файлов *без запуска установщика*, перезапуском и откатом при сбое старта. Приложение не запускает исполняемый файл из интернета; ZIP проверяется также перед распаковкой.
- Канал обновлений определяется автоматически из `${{ github.repository }}`; открытые адрес и ключ вставляются во время GitHub Actions сборки. Нужно **один раз** выполнить workflow `Circle signing key setup`, используя краткосрочный fine-grained PAT с правом Secrets read/write для своего репозитория. Ключ создаётся и сохраняется на стороне GitHub; локальный Python не требуется. Без установленного приватного ключа сборка останавливается — это намеренная защита от неподписанных релизов.
- Исправлена обработка `SERVER_ERROR` в профиле: при ошибке старого API появляется безопасный режим просмотра данных из `me`. В отдельном серверном патче исправлены уязвимые к несинхронным миграциям запросы профиля и профилей друзей.
- Добавлены нативные экраны регистрации и восстановления пароля, поиск пользователей и управление заявками в друзья (требуют серверный Mobile API hotfix).
- Снижено количество лишних запросов, добавлена ленивая отрисовка списков, ограниченный кэш аватаров, видео и аудио загружаются только по команде, потоковая загрузка мультимедиа и обновлений, задержка опроса звонков без наложения запросов.
- Доработана сдержанная графитовая/золотая тема на основе стиля сайта Circle 5.2.3. Четыре основные вкладки: Главная, Профиль, Мессенджер, Друзья. Остальные возможности доступны через вторичную навигацию.

## Начальная установка из GitHub Actions

1. Распакуйте **содержимое** этого ZIP в корень GitHub-репозитория; `.github/workflows/windows.yml` обязательно должен остаться скрытой папкой `.github`.
2. **Перед первой сборкой** запустите **Actions → Circle signing key setup**, предварительно добавив временный `CIRCLE_BOOTSTRAP_TOKEN` — см. `docs/GITHUB-AUTO-UPDATE.md`. После успеха удалите токен, запустите `Circle Windows build`.
3. Откройте **Actions → Circle Windows build → Run workflow** (или отправьте commit в `main`).
4. После успешных `flutter analyze`, `flutter test`, сборки и проверки Inno Setup скачайте из Artifacts `Circle-Windows-Setup`.
5. Установите `Circle_Windows_0.6.0_Setup.exe` **один раз**. Эта версия создаёт механизм будущих обновлений. Версии **0.4.2 и старше и сборки 0.5.0 без ключа не умеют сами обновляться до 0.6.0** — первый переход потребует однократной установки поверх с сохранением AppId.
6. Для работы профиля и новых функций друзей установите отдельно серверный патч `Circle_5.2.3_MobileAPI_0.6.0_COMPAT.zip`, предварительно сохранив резервную копию `api/mobile.php` и базы данных.

## Автообновления без переустановки (исправлено в 0.6.1)

**GitHub Actions → Artifacts не является каналом обновлений.** Установленное приложение обращается к `https://github.com/OWNER/REPO/releases/latest/download/update-manifest.json` и проверяет подпись Ed25519.

Начиная с этого исправления, **после успешной сборки из ветки `main` или `master`** workflow автоматически создаёт стабильный GitHub Release `v0.6.1` (и три файла: EXE, `*_Payload.zip`, `update-manifest.json`), если исходная версия **строго больше** опубликованной. Ручное создание тега больше не требуется. Увеличивайте номер версии при каждом обновлении бинарного клиента, например 0.6.1 → 0.6.2, иначе GitHub не выпускает повторный Release.

При ручном запуске workflow из основной ветки действует то же правило. Тег `vX.Y.Z` по-прежнему поддерживается, но обязан совпадать с номером версии исходников. Существующий тег другой сборки не перезаписывается. Репозиторий должен быть **публичным**, иначе незалогиненный Windows-клиент не сможет получить манифест и ZIP из Releases.

Если опубликованного релиза нет (HTTP 404), клиент 0.6.1 теперь показывает конкретную ошибку вместо ложного «Установлена актуальная версия». Когда найден подписанный релиз версии выше установленной, приложение предложит скачать проверенный ZIP, заменит файлы через `tools/apply_update.ps1` и перезапустится; пользователь не запускает Inno Setup повторно. **Установка в `%LOCALAPPDATA%\Programs\Circle`** должна позволять запись в каталог приложения. Первая установка клиента со встроенным публичным ключом необходима один раз.

Чтобы проверить 0.6.0 → 0.6.1: загрузите *только файлы патча* из ZIP обновления в корень GitHub-репозитория, убедитесь в успешной сборке **и публикации Release** во вкладке Releases. Запустите на компьютере установленный Circle 0.6.0 и нажмите «Проверить обновления». Приватный ключ в GitHub Secrets должен оставаться прежним. Если на компьютере уже 0.6.1, обновление 0.6.1 не появится — для следующего испытания потребуется релиз 0.6.2.

Журнал запуска: `%LOCALAPPDATA%\Circle\logs\startup.log`, журнал обновлений: `%LOCALAPPDATA%\Circle\updates\update.log`.

## Обновление сервера Circle 5.2.3

Патч меняет только `api/mobile.php`, без изменений SQL и существующих пользовательских данных. На сервере он должен попасть именно по пути `SITE_ROOT/api/mobile.php`. Проверка `php -l api/mobile.php` должна выдавать `No syntax errors detected`. Если ошибка `SERVER_ERROR` осталась, проверьте журнал PHP на хостинге: причина может быть не связана с необязательными таблицами, и её нельзя установить без серверного лога.

Смотрите `docs/API-COMPATIBILITY.md`. Поддерживаются вход/2FA, регистрация, сброс пароля через email, выход, лента и посты, истории, личные профили, друзья и запросы, мессенджер, вложения, аудиосообщения, комментарии, сообщества по приглашениям, текстовые каналы, реакции, звонки LiveKit на уровне кода, уведомления, часть настроек и сводка администратора. ## Исправление проверки установщика в CI

Если старая сборка завершалась на шаге `Verify installed runtime contents` с сообщением `Installer failed with exit code ` (без числа), проблема заключалась в вызове Inno Setup как GUI-процесса без ожидания его завершения. Скрипт `tool/verify_installer.ps1` теперь вызывает установщик через `Start-Process -Wait -PassThru`, проверяет его фактический `ExitCode`, затем проверяет runtime-файлы *после установки*.

Если реальная ошибка установки повторится, CI покажет последние строки `inno-install.log` и приложит артефакт `Circle-Installer-Diagnostics`. На этом этапе **не нужно менять ключ подписи или настройки GitHub Secrets**. Версия бинарного клиента остаётся `0.6.0`; это исправление CI, а не новый релиз функциональности.

## Как понять, что сборка прошла

GitHub Actions запускает анализ, Flutter tests, Windows build, Inno installer и проверку целостности установочного и ZIP-runtime. **До успешного GitHub Actions и тестов на настоящей Windows нельзя утверждать, что Windows EXE компилируется и все функции работают.** В текущей среде есть PHP/Python, но нет Flutter SDK, PowerShell Windows или Inno Setup.

Локальная сборка на Windows с Flutter, Visual Studio C++ и Inno Setup 6:

```powershell
./build-installer.ps1 -Repository OWNER/REPO -PublicKey BASE64_PUBLIC_KEY
```

Для первого релиза и всех будущих версий рекомендуется GitHub Actions, а не самостоятельная ручная сборка.

Диагностика запуска: `%LOCALAPPDATA%\Circle\logs\startup.log`; журнал обновлений: `%LOCALAPPDATA%\Circle\updates\update.log`. Сообщения и пароль в эти журналы не записываются.


## Новый этап 0.6.0: функции веб-версии

Добавлены **нативные** действия над собственными публикациями (заголовок, текст, комментарии, закрепление, удаление), репосты с возможностью отмены, удаление собственных комментариев, вкладка репостов профиля, редактирование обложки, выбор видимости профиля и начало диалога с другом из его профиля. Сервер проверяет авторство, дружбу и доступ к публикациям **до** операции. Нет отдельной базы или WebView.

**Обязательно установите companion API patch 0.6.0** поверх ранее установленного Mobile API hotfix (создайте резервную копию `api/mobile.php`). Старый Mobile API не знает новых маршрутов; без обновления сайта новые кнопки ответят `NOT_FOUND`. SQL миграций в патче нет. Полное совпадение функций веб-версии пока не заявляется: часть функций ролей, модерации, групповых звонков и кинозалов требует отдельного переноса и сквозного тестирования.
