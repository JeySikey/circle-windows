# Circle Windows Native 0.5.0 — самостоятельное приложение для Windows

**Приложение не использует WebView.** Интерфейс написан на Flutter, данные и пользовательские аккаунты поступают с Circle 5.2.3 по HTTPS Mobile API. Сайт остаётся на PHP/MySQL на обычном хостинге. База данных и пользовательский контент в установщик не входят.

## Что изменено относительно 0.4.2

- Создана система **подписанных GitHub Releases с автоматической проверкой при запуске**, запросом подтверждения, загрузкой полного ZIP-runtime, проверкой Ed25519/SHA-256, локальной заменой файлов *без запуска установщика*, перезапуском и откатом при сбое старта. Приложение не запускает исполняемый файл из интернета; ZIP проверяется также перед распаковкой.
- Канал обновлений определяется автоматически из `${{ github.repository }}`; открытые адрес и ключ вставляются во время GitHub Actions сборки. Нужно **один раз** настроить `CIRCLE_UPDATE_PRIVATE_KEY_PEM` в GitHub Secrets. Без ключа сборка возможна, но автоматические обновления отключены — это намеренная защита.
- Исправлена обработка `SERVER_ERROR` в профиле: при ошибке старого API появляется безопасный режим просмотра данных из `me`. В отдельном серверном патче исправлены уязвимые к несинхронным миграциям запросы профиля и профилей друзей.
- Добавлены нативные экраны регистрации и восстановления пароля, поиск пользователей и управление заявками в друзья (требуют серверный Mobile API hotfix).
- Снижено количество лишних запросов, добавлена ленивая отрисовка списков, ограниченный кэш аватаров, видео и аудио загружаются только по команде, потоковая загрузка мультимедиа и обновлений, задержка опроса звонков без наложения запросов.
- Доработана сдержанная графитовая/золотая тема на основе стиля сайта Circle 5.2.3. Четыре основные вкладки: Главная, Профиль, Мессенджер, Друзья. Остальные возможности доступны через вторичную навигацию.

## Начальная установка из GitHub Actions

1. Распакуйте **содержимое** этого ZIP в корень GitHub-репозитория; `.github/workflows/windows.yml` обязательно должен остаться скрытой папкой `.github`.
2. **Перед первой сборкой** настройте секрет подписи — см. `docs/GITHUB-AUTO-UPDATE.md`.
3. Откройте **Actions → Circle Windows build → Run workflow** (или отправьте commit в `main`).
4. После успешных `flutter analyze`, `flutter test`, сборки и проверки Inno Setup скачайте из Artifacts `Circle-Windows-Setup`.
5. Установите `Circle_Windows_0.5.0_Setup.exe` **один раз**. Эта версия создаёт механизм будущих обновлений. Версии **0.4.2 и старше не умеют сами обновляться до 0.5.0** — первый переход потребует однократной установки поверх с сохранением AppId.
6. Для работы профиля и новых функций друзей установите отдельно серверный патч `Circle_5.2.3_MobileAPI_HOTFIX.zip`, предварительно сохранив резервную копию `api/mobile.php` и базы данных.

## Автообновления без переустановки

Новые релизы публикуются тегами `v0.5.1`, `v0.5.2` и так далее. Подробная инструкция — `docs/GITHUB-AUTO-UPDATE.md`. GitHub Actions сам собирает портативный ZIP из всего Flutter Release runtime (а не только EXE), подписывает метаданные через Ed25519 и прикладывает три актива: установщик (для новых пользователей), ZIP-пакет (для обновлений) и `update-manifest.json`.

Уже установленная Circle (начиная с 0.5.0 с настроенным ключом) при запуске проверяет `https://github.com/OWNER/REPO/releases/latest/download/update-manifest.json`. После подтверждения приложение скачивает ZIP, проверяет подпись/хэш, запускает **внешний** `tools/apply_update.ps1`, завершает старый процесс, заменяет папку установленной программы, открывает новую версию. Если новая программа сразу завершается, выполняется попытка отката. Пользователь не скачивает установщик и не выполняет его вручную.

**Важные условия:** GitHub-репозиторий и GitHub Release должны быть доступны для скачивания без авторизации; первоначальная установка должна быть *на пользователя* в `%LOCALAPPDATA%\Programs\Circle` (не защищённая Program Files); подпись должна быть действительной; во время обновления не должен работать второй экземпляр программы. В рабочей сборке важно проверить обновление на реальной Windows: в этой среде Windows toolchain отсутствует.

## Обновление сервера Circle 5.2.3

Патч меняет только `api/mobile.php`, без изменений SQL и существующих пользовательских данных. На сервере он должен попасть именно по пути `SITE_ROOT/api/mobile.php`. Проверка `php -l api/mobile.php` должна выдавать `No syntax errors detected`. Если ошибка `SERVER_ERROR` осталась, проверьте журнал PHP на хостинге: причина может быть не связана с необязательными таблицами, и её нельзя установить без серверного лога.

## Реально реализованные функции и ограничения

Смотрите `docs/API-COMPATIBILITY.md`. Поддерживаются вход/2FA, регистрация, сброс пароля через email, выход, лента и посты, истории, личные профили, друзья и запросы, мессенджер, вложения, аудиосообщения, комментарии, сообщества по приглашениям, текстовые каналы, реакции, звонки LiveKit на уровне кода, уведомления, часть настроек и сводка администратора. Сложное управление правами и ролями, полный веб-инструментарий модерации, Windows Push, все групповые видео/кинозалы пока не имеют полноценного публичного Mobile API и не заявляются как реализованные.

## Как понять, что сборка прошла

GitHub Actions запускает анализ, Flutter tests, Windows build, Inno installer и проверку целостности установочного и ZIP-runtime. **До успешного GitHub Actions и тестов на настоящей Windows нельзя утверждать, что Windows EXE компилируется и все функции работают.** В текущей среде есть PHP/Python, но нет Flutter SDK, PowerShell Windows или Inno Setup.

Локальная сборка на Windows с Flutter, Visual Studio C++ и Inno Setup 6:

```powershell
./build-installer.ps1 -Repository OWNER/REPO -PublicKey BASE64_PUBLIC_KEY
```

Для первого релиза и всех будущих версий рекомендуется GitHub Actions, а не самостоятельная ручная сборка.

Диагностика запуска: `%LOCALAPPDATA%\Circle\logs\startup.log`; журнал обновлений: `%LOCALAPPDATA%\Circle\updates\update.log`. Сообщения и пароль в эти журналы не записываются.
