# Codex instructions: Circle Windows

Нативный Flutter Windows клиент **0.10.0 (кандидат)**, не WebView. Прочитать `docs/codex/CODEX_HANDOFF.md`, `README.md`, `docs/GITHUB-AUTO-UPDATE.md` и общий handoff.

1. Базовый Windows 0.9.0 подтверждён последним логом: все 27 Flutter-тестов прошли, включая модерацию. Сохранять эти проверки; не ослаблять безопасность ради CI. Текущий фокус пользователя — дизайн, навигация и отзывчивость Windows.
2. Затем end-to-end проверить in-place updater: GitHub Releases → Ed25519/SHA-256 → ZIP → handshake → внешняя замена файлов → автозапуск → rollback, на Windows 10/11. Проверки updater в CI 0.9.0 прошли; пользователь подтвердил, что обновления на его ПК работают. Изменения UI не требуют переделки updater.
3. Не менять неизменно сохранённый приватный signing key и не коммитить его. Публичный ключ допускается внутри бинарника.
4. Развивать собственные нативные экраны под **все функции веба**; если API нет, добавить защищённый маршрут на сервере. Не добавлять WebView как замену функциональности.
5. Новый GitHub патч = **только изменённые/новые файлы**, список удалений, CHANGELOG и тесты. Этот repo — полный bootstrap по отдельному запросу пользователя.
6. Дизайн: современный графитово-золотой, мягкий неон, анимации в меру, адаптация окна, доступность и измеримая оптимизация.
7. Не публиковать `vX.Y.Z`, пока CI и ручной Windows smoke-test не пройдены; пользовательские данные должны храниться вне каталога заменяемых бинарников.

Текущая итерация и порядок проверки: `docs/UI-0.10.0.md`. Android не входит в её объём.
