# План тестирования Circle Windows 0.6.0

## Сборка

- GitHub Actions: `flutter analyze --no-fatal-infos`, `flutter test`, `flutter build windows --release`, `Inno Setup`, проверка ZIP и файлов установленного runtime.
- Установить 0.6.0 поверх 0.4.2 и отдельно на чистую Windows 10/11 x64. Не удалять пользовательские данные.
- Проверить запуск, системный журнал, Secure Storage и безопасное восстановление сессии после временного пропадания сети.

## API и страницы

- После установки server hotfix открыть профиль, изменить ник и описание, загрузить фото, открыть публикации.
- Проверить регистрацию, 2FA, сброс пароля (SMTP), выход.
- Создание поста/истории, комментарии и ответы, реакции, фото/видео.
- Друзья: поиск, входящая и исходящая заявки, принятие/отклонение/отмена/удаление.
- Мессенджер: файл, голосовое, ответ и реакции; протестировать разные аудиоформаты.
- Сообщества по приглашению, каналы и права доступа; звонки (микрофон, камера, LiveKit).
- Нагрузка: прокрутка длинной ленты, пиковое использование памяти, скролл с медиа, свернутое окно.

## Автообновление — обязательно

1. Установить подписанную 0.6.0 с публичным ключом, полученным из GitHub Actions.
2. Опубликовать подписанный релиз 0.6.0 по инструкции, не меняя ключ подписи.
3. Запустить старую программу; проверить окно подтверждения.
4. Выбрать «Позже»: ничего не должно скачаться/измениться.
5. Выбрать «Обновить»: ZIP проверяется и скачивается; старое окно закрывается, новая версия стартует автоматически; в меню показывается новая версия.
6. Подменить байт ZIP и проверить отказ по SHA-256. Изменить подписанный манифест без переподписи — ожидается отказ Ed25519.
7. Искусственно испортить тестовый релиз и проверить откат; проверить логи `%LOCALAPPDATA%\Circle\updates\update.log`.
8. Повторить проверку без интернета, с отсутствующим Release, при загруженном большом ZIP и при одновременном втором экземпляре.

Нельзя заявлять о прохождении этих пунктов до реального тестирования.


## Ручная проверка новых возможностей 0.6.0

Перед тестированием сделайте backup сайта и установите серверный companion patch. Не проводите опасные тесты удаления на важных пользовательских данных.

1. Создайте *тестовую* публикацию; проверьте редактирование заголовка и текста, выключение комментариев и их включение снова.
2. Закрепите тестовую USER-запись и открепите её; проверьте после перезагрузки.
3. Перепубликуйте чужую доступную запись, откройте «Репосты» в профиле, отмените репост, проверьте счётчики.
4. Создайте комментарий и ответ; удалите родительский от автора. Ответ должен остаться доступным.
5. Откройте профиль другого пользователя: кнопку «Написать сообщение» разрешить только друзьям. Проверьте, что повторное открытие использует старый диалог.
6. Загрузите новую обложку JPG, затем PNG; проверьте отображение после перезапуска. Проверка 10+ МБ должна отклоняться.
7. Проверьте настройки видимости профиля с двух тестовых аккаунтов, включая отказ при недоступном профиле.
8. Проверьте доступ запрещённого участника к сообществу, отсутствие прав на редактирование чужой записи и попытки запросов без токена.
9. Для каждого нового UI-действия проверьте ответ `FEATURE_DISABLED` при выключении соответствующей функции администратором.
10. Проверьте, что переход с 0.5.1 на подписанный GitHub Release 0.6.0 не меняет аккаунт, папку установки и пользовательские данные; нужен прежний публичный ключ.

Только после GitHub `flutter analyze`, `flutter test` и функциональной проверки на реальной Windows отмечайте функцию как проверенную.
