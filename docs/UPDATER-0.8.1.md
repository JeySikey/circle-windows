# Circle Windows 0.8.1 — исправление запуска и диагностики обновлений

По диагностике 11.11.2026 ZIP скачан, файлы `circle_windows.exe` и `tools/apply_update.ps1` в папке установки существуют (строки `Found: False` означали `PSIsContainer=False`). Журнал отсутствовал. Реальную причину завершения PowerShell определить не удалось: режим запуска `detached` скрывал stderr и код выхода, а каталоги диагностики не совпадали.

В 0.8.1 `launcher.log` создаётся ДО запуска PowerShell в `%LOCALAPPDATA%\Circle\updates`. Клиент читает stdout/stderr, видит код завершения, ждёт готовности до 120 секунд и не закрывается при ошибке. Папка диагностики совпадает с PowerShell `update.log`.

## Порядок проверки

1. Загрузить файлы патча в GitHub (поверх 0.8.0), не удаляя остальные исходники; дождаться проверок CI и GitHub Release `v0.8.1`.
2. Поскольку установленный клиент 0.8.0 может НЕ применять обновления, для перехода 0.8.0 → 0.8.1 возможно понадобится один раз запустить `Circle_Windows_0.8.1_Setup.exe` поверх текущей версии. Не удалять предыдущую версию и локальные данные.
3. Выпустить версию 0.8.2 и проверить автоматическое обновление **0.8.1 → 0.8.2** по подписанному ZIP: подтверждение → скачивание → установка → перезапуск. Только этот реальный тест подтверждает исправность механизма.
4. Если ошибка повторяется, открыть `%LOCALAPPDATA%\Circle\updates\launcher.log` (или `update.log`) и отправить последние строки. Если Windows блокирует PowerShell, не отключать Защитник Windows — прислать текст ошибки.

Проверки в этой поставке — статические и unit test; локальный запуск Windows Flutter не проводился.
