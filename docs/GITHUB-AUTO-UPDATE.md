# Circle Windows 0.6.0 — автоматическая генерация ключа в GitHub Actions

Ключ подписи Ed25519 создаётся **на сервере GitHub Actions**, не на твоём ПК. Python локально не требуется. Публикуется только публичный ключ, приватный сохраняется в зашифрованном GitHub Actions repository secret.

## Один раз: разрешить запись секрета из GitHub Actions

Стандартный `GITHUB_TOKEN` не обладает доступом для создания repository Actions secrets. Поэтому для первоначальной настройки нужен **временный fine-grained personal access token (PAT)**, ограниченный одним репозиторием. См. официальные [права GitHub Secrets API](https://docs.github.com/en/rest/authentication/permissions-required-for-fine-grained-personal-access-tokens).

1. Открой GitHub → аватар → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Выбери **Repository access: Only select repositories** и укажи репозиторий Circle Windows.
3. В **Repository permissions → Secrets** выбери **Read and write** (Metadata: Read — предоставляется автоматически). Других прав не требуется. Поставь короткий срок действия, например один день.
4. Скопируй токен, открой репозиторий → **Settings → Secrets and variables → Actions → New repository secret**. Название: **`CIRCLE_BOOTSTRAP_TOKEN`**, значение: скопированный PAT. Не вставляй PAT в Issues, README, chat или репозиторий.

## Запуск генерации

1. В репозитории из этого ZIP на ветке по умолчанию открой **Actions → Circle signing key setup → Run workflow**.
2. Дождись успешного завершения и открой **Summary**. В GitHub repository secret `CIRCLE_UPDATE_PRIVATE_KEY_PEM` автоматически появится приватный ключ. **Ни ключ, ни приватный PEM не публикуются в Actions logs / artifacts**.
3. Публичный ключ (`PUBLIC_KEY_BASE64`) будет напечатан в логе и Summary — его показывать можно, он не секретный. Передавать его в чат необязательно.
4. **Сразу удали `CIRCLE_BOOTSTRAP_TOKEN` из Secrets и отзови созданный PAT** в GitHub Settings → Developer settings. Он больше никогда не потребуется для сборок или обновлений.
5. После этого запусти **Actions → Circle Windows build → Run workflow**. Уже существующие секреты подтянутся в новую сборку. GitHub Actions выведет публичный ключ из приватного, встроит его в EXE и подпишет релизный манифест.

**Важно:** не запускай bootstrap повторно ради новых версий! Скрипт откажется перезаписывать существующий секрет, чтобы не сломать автообновление старых клиентов.

## Сборка установщика / первый запуск

В `Actions → Circle Windows build` скачай артефакт `Circle-Windows-Setup` и один раз установи Circle 0.6.0. Версии, собранные без встроенного ключа, не могут самостоятельно научиться проверять подписи: **при переходе с такой сборки нужна однократная переустановка поверх неё**. Все последующие релизы на том же ключе смогут устанавливаться без запуска нового установщика.

## Публикация нового подписанного релиза

- Создай тег `v0.6.0` из commit с версией 0.6.0. Workflow опубликует GitHub Release с файлами `Circle_Windows_0.6.0_Setup.exe`, `Circle_Windows_0.6.0_Payload.zip`, `update-manifest.json`.
- Для проверки автообновления после установки 0.6.0 выпусти **0.6.1** (увеличь номер в `pubspec.yaml`, `lib/main.dart`, `installer/Circle.iss`, `.github/workflows/windows.yml`, `tool/validate_package.py`, `build-installer.ps1`), затем создай тег `v0.6.1`.
- Клиент 0.6.0 увидит новый Release, попросит разрешение, проверит подпись/хэш, скачает ZIP, заменит бинарники через отдельный процесс и перезапустится.
- Релизы должны быть публично доступны, и в GitHub Release должна быть опубликована именно **новейшая стабильная версия**; черновики и prerelease не подходят для `/releases/latest`.

## Безопасность и ограничения

- `CIRCLE_UPDATE_PRIVATE_KEY_PEM` **нельзя удалять или менять** без специальной процедуры ротации. GitHub не позволяет читать созданные Secrets обратно: утрата ключа делает последующие обновления старых приложений невозможными. Для долгосрочного производства следует предусмотреть защищённую резервную копию при первоначальном создании или процедуру двухключевой ротации; в этой версии восстановление приватного ключа из GitHub Secrets отсутствует.
- `CIRCLE_BOOTSTRAP_TOKEN` — временный токен только для первого запуска; удалить его и отозвать после успешного выполнения.
- Клиент скачивает полный runtime ZIP, а не инкрементальный бинарный патч. Обновление не запускает установщик, но заменяет файлы приложения и требует прав на изменение каталога установки.
- Репозиторий и Releases должны быть доступны клиентам без авторизации, иначе запрос `/releases/latest` не сработает.
- Успешные статические проверки не гарантируют реальное обновление под Windows: проведи тест перехода 0.6.0 → 0.6.1 на тестовой машине.
