# Circle Windows 0.11.0 — системные уведомления

## Что реализовано

- Windows toast (не Flutter-окно поверх приложения), с системным звуком, иконкой Circle и идентификатором AUMID `ru.acircle.circle.windows`.
- Нажатие на toast возвращает свёрнутое приложение на передний план и открывает нативную переписку, запись, друзей и заявки, сообщество, текстовый канал либо голосовую встречу (по имеющимся полям события).
- Для кинозала используется нативный раздел кинозалов; переход сразу в комнату потребует отдельного API/экрана.
- Центр уведомлений: вкладки, отметка прочитанного, массовое прочтение, пагинация, переход к объекту события, настройки категорий.
- Индикатор непрочитанного на колокольчике, отдельные пользовательские переключатели звука и всплывающих окон.
- Опрос только при активной авторизованной сессии, сериализованный, раз в 18 секунд. Идентификатор последнего события хранится отдельно для каждого пользователя/сервера в Windows Secure Storage. При первом запуске старые уведомления не всплывают повторно.
- Текст сообщений, содержимое публикаций и прямые URL из серверного payload не передаются в toast. Только тип события, имя отправителя и разрешённые цифровые ID.

## Обязательная совместимость

**До первого запуска Windows 0.11.0 установите серверный патч `api/mobile.php` из отдельного ZIP.** Сохраните резервную копию исходного файла и БД сайта.

API-маршруты:

- `GET /api/mobile.php?route=notifications` — последние 40, с `before=ID` старый контракт для исторической пагинации.
- `GET /api/mobile.php?route=notifications&after=ID` — новые события по ID, максимум 40, в возрастающем порядке (для Windows).
- `GET /api/mobile.php?route=notification-one&id=ID` — только принадлежащее пользователю событие, для обработки клика после перезапуска.
- `POST /api/mobile.php?route=notification-read` — прочтение одного события или всех.
- `GET /api/mobile.php?route=post-detail&id=ID` — запись с проверкой авторства, дружбы, членства в сообществе и блокировок.

## Чек-лист ручной проверки Windows

1. Соберите `v0.11.0` в GitHub Actions; перед публикацией убедитесь, что `flutter analyze` и `flutter test` зелёные.
2. Установите клиент, войдите в один аккаунт, закройте все окна центра уведомлений; из второго аккаунта отправьте сообщение.
3. В течение ~18–40 секунд должен появиться toast Windows со звуком, если разрешено системой и в Circle.
4. Нажмите на toast при **свёрнутом** Circle: приложение должно открыться на конкретной переписке. Проверьте отдельно комментарий к публикации, заявку в друзья, упоминание в канале и голосовую встречу.
5. Убедитесь, что событие не всплывает повторно после последующего опроса и перезапуска Circle.
6. Выключите «Звук Windows» и повторите: toast отображается бесшумно. Выключите всплывающие уведомления — счётчик в приложении остаётся рабочим.
7. Проверьте системные «Не беспокоить» и запрет уведомлений для Circle; приложение не должно обходить эти настройки.
8. Проверьте два разных аккаунта на одном ПК, отсутствие чужих уведомлений после выхода и исчезновение приватного текста из toast.
9. Проверьте пагинацию истории и массовое прочтение; тестируйте с 45+ уведомлениями.
10. Проверьте скорость прокрутки мессенджера и ленты при открытом центре уведомлений. Минимизируйте Circle и повторите получение сообщения.

## Ограничения и дальнейшие этапы

- События приходят при **работающем процессе Circle**. Если пользователь полностью вышел из программы, текущая версия не получает push — для этого потребуется фоновый Windows-процесс/служба или централизованный пуш-сервис.
- Опрос раз в 18 секунд не гарантирует мгновенного появления; может зависеть от сети, системной экономии энергии и Windows Focus Assist.
- Реальную систему toast-уведомлений, звук и обработчик клика необходимо подтвердить на Windows 10/11. Локальная среда разработки не содержит Windows/Flutter toolchain.
- Полный перенос кинотеатров, админки и всех видеоконференций не завершён и не должен считаться пройденным на основании наличия UI.
- На публичном GitHub никогда не размещать приватный ключ подписи обновлений, токены LiveKit и SMTP-пароли.
